# company_lab — agent guide

Fundamentals **quality + valuation ranking over the S&P 500**, built to a fixed
94-point framework the user authored (100 until E26). SEC EDGAR XBRL companyfacts supplies the
statements; yfinance supplies price, multiples and analyst estimates; a local
Ollama model scores the two judgement components (SG, BQ). Output is a phone-first
dashboard on `127.0.0.1:8100`, a `scores.parquet`, a CSV, and a formatted 12-sheet
`.xlsx` (DCF was added after this line first said 11). **Excel is installed (since 2026-08-12) and the workbook is now the
primary weekly artifact** — the user opens `data\exports\company_lab_latest.xlsx`,
a stable name the crawl refreshes beside the dated archive.

**Long-horizon investing decision support. Not a trading signal, not a broker
client, not a validated model.** Nothing here places an order or feeds one.

Skills: load `win-quant-env` before installs / git / `.ps1` / Task Scheduler work,
`quant-research-gate` before touching scoring thresholds or making any claim that
this ranking predicts returns.

## Hard rules

1. **Advisory / SHADOW, always.** `promoted` is `false` in every flag file and
   there is no code path that sets it true. This ranking has never been tested
   against forward returns. Do not add a claim that it works; add the grader
   first (§Deferred).
2. **Absent data is `NO_DATA`, never `0`.** A company with no interest-expense tag
   is not a company with terrible interest coverage. `earned=None,
   status=NO_DATA` is structurally distinct from `earned=0, status=SCORED`, and
   `tests/test_composite.py` pins the distinction.
3. **Below 80% coverage a company gets NO band.** `INSUFFICIENT_DATA`, not a
   flattering label. Assigning "High Conviction" on 60% of the framework would be
   the most dangerous thing this system could do.
4. **Sub-test scores are integers.** A 3.7/4 implies precision the accounting does
   not have. An out-of-range LLM score is **rejected, never clamped** — clamping
   would launder a hallucinated 9/4 into a top score.
5. **The LLM never sits on a request path.** `clab/ui/app.py` does not import
   `clab.qual`; `tests/test_export_and_ui.py::test_ui_never_imports_the_llm_scorer`
   asserts it. SG/BQ are read from a disk cache written by an offline batch. A
   cold cache means those components are `NO_DATA` — never a neutral midpoint.
   **A cold cache costs MG nothing**: MG is fully measured, and its payload supplies
   only a display-only summary string. The same rule now applies to `clab.external`,
   which the UI must also never import.
6. **The dashboard binds `127.0.0.1` only.** Port 8100. Never `0.0.0.0`, never
   tunnelled. The string `0.0.0.0` must not appear in `clab/ui/app.py` and a test
   checks that too.
7. **Bulk data lives on D:.** C: is the slow SATA spinner. `ensure_data_root()`
   returns False when D: is unavailable and the crawl **refuses to start** rather
   than dumping ~GB onto C:.
8. **Probe before a long crawl.** A crawl over 50 companies is refused unless a
   probe report younger than 7 days exists (`--i-know` overrides). Measured
   2026-08-08: 3.6 s/company, ~30 min for 500, ~0.1 GB.
9. **Snapshots cannot be backfilled.** `CompanyLabSnapshot` runs weekly from day
   one. Every week it does not run pushes the forward-return grader a week out.
10. **A missing comparison is never "cheap".** Own-history percentiles need
    accumulated snapshots and peer medians need >= 5 scored peers; without them
    the valuation sub-test abstains.
11. **A NULL from the judged half proves nothing.** Contamination cuts BOTH ways —
    see the section immediately below. This is a rule because this project keeps
    producing nulls and they are easy to over-read.

## Contamination runs in BOTH directions, so a null is not a result

The judged half is generated by a local model whose pretraining corpus overlaps most of
the label window — `qwen2.5:7b`'s data predates 2024, while the E04 panel's labels run
**2016-01 to 2026-08**. Glasserman & Lin's look-ahead-bias work is usually cited for one
direction. The other one is the trap here.

**Direction 1 — inflation, the familiar one.** The model has read what happened next, so
its "judgement" about a 2019 10-K can encode the outcome rather than the filing. Apparent
skill appears where none was earned.

**Direction 2 — depression, the one that matters for reading our own results.**
Contamination is **uneven**. It is stronger for prominent companies than obscure ones, and
stronger inside the pretraining window than after it. So a procedure fitted or selected on
the contaminated portion carries assumptions that do not transfer, and the out-of-sample
measurement comes back **biased downward**. A clean-looking null is therefore consistent
with at least three worlds:

  1. there is no signal;
  2. there is a signal, masked because the selection step ran on contaminated data;
  3. there is a signal in some companies and not others, and the split is contamination,
     not economics.

**Nothing in this repo can currently distinguish them.** So a judged-half null — E22's
included — is **not** evidence of no signal, and must never be written up as one. The
measured-half nulls (E13, E05) are unaffected by this: `panel.py` excludes the LLM half by
construction.

**And it is entangled with the size tilt we already measured.** Prominence correlates with
market cap, and Spearman(score, log market cap) is **0.319**. Contamination and the size
tilt cannot be separated on the current design — which means neither can be cleanly
attributed until one of them is fixed.

**The only clean tests** are a holdout that starts after the scoring model's knowledge
cutoff, or a model whose cutoff precedes the entire label window. Both cost a re-score of
the judged half. Until one exists, say "untested", never "does not work".

## Framework: 94 points, and the halves are no longer equal

**It was 100 points and a 50/50 split until 2026-08-23.** E25 removed MG's five
model-scored CEO attributes (E22 measured the block's year-over-year stability at 0.29;
E24 proved the proxy statement fixed *availability* and not *reliability* — `tenure`, a
fact that increments by one a year, round-tripped at kappa 0.29). E26 then shrank the CEO
block from 8 points to 2, because leaving it at 8 made **deleting a question make the
framework easier to pass** — 56 companies crossed the band gate on threshold arithmetic
alone.

| Half | Components | Source |
|---|---|---|
| **Measured /59** | FE 18, **MG 9**, BS 10, VA 15, ER 5, EN 2 | EDGAR + yfinance, fully auditable |
| **Judged /35** | SG 20, BQ 15 | local LLM, **no human review step** (the user's explicit choice) |

**This table said /50 and /44 until 2026-09-01, and it was wrong** — see the MG entry
under Gotchas. The constants are `rubric.MEASURED_COMPONENTS` (59),
`rubric.JUDGED_COMPONENTS` (35) and `rubric.GENERATED_COMPONENTS` (what the qual
pipeline asks for, which still includes MG). Never quote the split from prose again;
`rubric.points_in()` knows it.

**`composite_strict` is not comparable to any figure quoted before 2026-08-23**, and every
study on the Findings sheet predates the change. The BAND score is a different number:
`composite.selection_score` normalises the ex-entry sum to **100** explicitly, so
`rubric.BANDS` keeps its calibration however many questions the framework asks. The
headline sum and the banded score therefore live on different scales — deliberate, tested,
and worth knowing before reading them side by side.

**MG is fully measured /9**, not a mixture: guidance hit-rate from the surprise
history, downturn survival from the filed revenue/margin series, and the whole
capital-allocation block from filed capex/R&D/buybacks/M&A/impairments. E25 removed its
five model-scored CEO attributes and `mg._LLM_ATTRS` has been an empty tuple ever since.
Every sub-test carries `provenance.source`, and the UI marks judged points with a purple
`LLM` chip — MG no longer gets one.

`composite_strict` (the raw point sum) is the headline. `composite_normalized`
extrapolates from what was scored and is never shown without its coverage figure.
`quant_normalized` / `quant_band` rescale the measured half to 0-100 so the
system is usable before the LLM half exists.

**Weight reconciliation:** every framework weight equals
`max_points/rubric.TOTAL_POINTS` and they sum to 1.00, so the weighted-normalized form and the raw point sum are
arithmetically identical. `test_weights.py` asserts agreement to 1e-9 over 10,000
random vectors so the two can never drift.

**The applicability map was measured and REFUSED (E29, 2026-08-25).** A REIT is still
asked about backlog and TAM, on purpose. Of 132 (sub-test, sector) pairs exactly one
cleared the null-rate criteria and it failed E12's P3, the written-business-reason test.
The predicted winner — `sg_capacity_backlog_contracts` for Real Estate — failed outright:
**34.9% of REITs were scored on it**, because a long-term lease *is* contracted forward
revenue. **Do not reopen this on a null rate.** The two rules that decided it:
`clab/research/e29_applicability.py` is the instrument, and the reasoning is in
`journal/experiments/E29_applicability_map.md`. Two things worth carrying:
- **On the judged half, `NOT_APPLICABLE` is a ONE-condition rule wearing a two-condition
  rule's clothes.** `resolve_status` needs profile nomination AND a genuinely absent
  value; for an LLM sub-test "value absent" IS "the model abstained", so nominating a
  judged key converts every abstention in that sector into `NOT_APPLICABLE`, drops it out
  of the coverage denominator and lifts companies over the 0.80 band gate — a large,
  self-flattering effect from a one-line edit. Rule C (best sector at or under 40% null)
  is the only thing standing in the way.
- **Category error and scored shortfall are never added.** Real Estate loses 1,527 judged
  points to questions it was never assessed on and 1,275 to questions the model DID assess
  and scored low; only the first was ever in scope, and **every sector's shortfall exceeds
  its category error**. Financials lose more to category error than Real Estate does.

## Hard-won gotchas (all measured on real filings — do not re-derive)

- **A CONSTANT CAN GO STALE THE SAME WAY A DOCSTRING DOES, and it is worse, because
  code reads it.** `rubric.LLM_COMPONENTS` listed MG. That stopped being true at E25
  (five model-scored CEO attributes removed) and E26 (block 8 → 2, component 15 → 9),
  and nothing followed it for two experiments. So **MG's 9 measured points were counted
  as model judgement**: inside `qual_only_50`, outside `quant_only_50` /
  `quant_normalized` / `quant_band` / `quant_coverage`. Measured blast radius on the
  live 1,501-row book: **`quant_band` was wrong for 297 companies (19.8%)**, and
  `INSUFFICIENT_DATA` went 129 → 176 once MG's own `NO_DATA` points stopped being hidden
  in the judged half — 47 companies had been given a measured-half band they had not
  earned the data for. The headline `score`, the bands and every rank were unaffected;
  only the attribution was wrong. Three lessons:
  - **One name was doing two jobs.** "Which components does the model generate" and
    "which points are judgement" were the same question until E25 and are not now. They
    are now `GENERATED_COMPONENTS` and `JUDGED_COMPONENTS`, and MG is in the first only.
    Deleting MG from the generation list would have silently dropped its `ceo_summary`
    rationale from every scorecard — a data loss wearing a cleanup's clothes.
  - **A settled study keeps the definition it ran under.** `e37_downgrades.py` is pinned
    to a module-local `("FE","BS","VA","ER","EN")`; repointing it would have changed
    numbers already written to `E37_results.json`.
  - **Stale payloads outlive the schema that made them.** The v1 lane still holds MG
    payloads with real 0-2 scores on the five removed attributes. They are inert only
    because no attribute has source `"llm"`. Re-mark one and months-old model opinions
    come back to life across the whole book, presented as current.
    `tests/test_mg_is_measured.py` pins the inertness rather than assuming it.
  Full record: `journal/experiments/mg_label_correction.md` (+ `.parquet`).
- **This box crashes often enough that a long lane needs a Scheduled Task, not a shell.**
  On 2026-08-31 it took **five unclean shutdowns in one day** (01:08, 08:03, 11:07,
  19:32, 21:44) and was **down 11:07→15:51 unattended**. A lane launched from any shell
  dies with the box and nobody notices. `scripts/resume_control_lane.ps1` is registered
  as `E38ControlLaneResume` — at-logon plus a 30-minute repeat, `IgnoreNew` so it never
  doubles up, and it disables itself at 1,471 companies. The lane is cache-resumable, so
  a crash then costs one batch instead of a night. **Diagnose a dead lane from the System
  event log (`Id=41,6008`) BEFORE blaming the process tree** — the first write of this
  rule blamed a detached-ollama mistake for ten lost hours that were actually a crash and
  a 4h45m outage.
- **A running `ollama` is not a working `ollama` — assert the GPU, not the port.** GPU
  discovery happens ONCE at startup with a **90 s per-backend watchdog**. On 2026-09-01
  it ran during the morning storm (boot + Defender QuickScan + the task launches, all on
  the C: spinner), every backend blew the watchdog with `lines_captured=0`, and ollama
  fell back to **CPU for the life of the process**. It answered `/api/tags` normally the
  whole time. That is not a slower run, it is a different one: **660-702 s/company on CPU
  against ~50 s on the GPU** — 13x, or 67 hours for what was left of the lane. The card
  was healthy throughout (`nvidia-smi` fine, 35 C) and the backend DLLs read clean, so
  **do not go hunting hardware**: kill ollama and start it again on a quiet box and
  discovery takes ~10 s. `resume_control_lane.ps1` now runs a 1-token generate and
  requires `size_vram > 0` from `/api/ps`, restarting ollama up to 3 times, and refuses
  to score CPU-only.
- **`ollama serve` still must be started detached**, whatever killed it last. Started from
  an agent background task it is a child of that task and dies when the task is torn down.
  Launch it with `Start-Process ollama serve -WindowStyle Hidden -RedirectStandardOutput
  <log>`, and check `tasklist | grep ollama` before trusting a long run. GPU discovery
  takes minutes here and falls back to Vulkan when the CUDA probe times out, so **wait on
  `GET /api/tags`, not on the process existing**.
- **A lane's own log going quiet is the only symptom of any of this.** The driver keeps
  its `.out` buffered, so it looks alive indefinitely. Check the payload count, not the
  driver.
- **A payload written at the moment of an unclean shutdown is NUL, not truncated.** The
  power fault on 2026-08-31 left `MAC`'s MG as 1,771 bytes of zeros: NTFS had sized the
  file and never flushed it. It still satisfies "the file exists", so
  **the resume logic counted MAC done and skipped it.** Scan for a NUL first byte after
  any hard stop — `python scripts/audit_payload_cache.py <cache_dir> --quarantine <dir>`
  does it — and the next resume regenerates what it moves aside. All three caches were
  clean after the 22:08 crash, so this is not a per-crash certainty; check anyway.
- **An interrupted `cp -r` reports nothing.** The same fault stopped the E37 snapshot
  copy at 278 of 1,473 scorecards with no exit code, because the shell died with it.
  After any interrupted copy compare **file counts**, and `md5sum` the parquet against
  the live one before a study reads the snapshot.
- **A retired XBRL tag must not supply the recent series.** NVDA stopped filing
  `RevenueFromContractWithCustomerExcludingAssessedTax` after FY2022 and moved to
  `Revenues`. Naive chain order gave a revenue series ending in 2020 and a "TTM
  revenue" of $10.9B against a true ~$200B. `tags.resolve()` merges the whole
  chain, lets only non-retired tags supply the recent end (`STALE_TAG_DAYS = 400`),
  and records every contributing tag in provenance.
- **`frame` is lossy and cannot be the series backbone.** NKE has 44
  quarter-duration rows and only 25 framed; COST skips CY2025Q2 and Q3 entirely.
  Classify by **duration**; use `frame` only as a peer-alignment key.
- **Cash-flow facts are cumulative and mixed.** AAPL operating cash flow arrives
  as a mix of qtr/half/9mo/ann rows. Quarters are derived explicitly
  (`Q2 = H - Q1`, `Q3 = 9M - H`, `Q4 = FY - 9M`) and a derived quarter far below
  the trailing mean is dropped as `suspect_decumulation` rather than scored.
- **Restatements are explicit — up to 4 rows share one `(start, end)`.** Dedupe by
  `max(filed)` for today's view, `min(filed)` for the point-in-time view the
  future grader must use. Walk the group in preference order and take the first
  row that *converts*: picking only the single newest row drops the whole quarter
  when the latest filing carries a malformed value.
- **`company_tickers.json` can point at a shell registrant.** It maps XOM to CIK
  `0002115436`, whose companyfacts holds 4 revenue rows; the real 127-row history
  is under `0000034088`, which is visible in the accession-number prefix.
  `resolve_facts()` follows that pointer automatically.
- **Some filers have no gross-profit or operating-income line at all.** JPM and
  XOM file neither; JPM also has no `AssetsCurrent`, capex or R&D. Operating income
  is reconstructed as `pretax income + interest expense` (standard EBIT), and a
  genuinely absent line reads `NOT_APPLICABLE`, which keeps coverage intact.
- **`NOT_APPLICABLE` requires both profile nomination AND actual absence.** UNH is
  SIC 6324 (nominally a FINANCIAL filer) but files a complete ordinary income
  statement. Suppressing its sub-tests on the SIC code alone would throw away real
  measured signal on a $450B-revenue company.
- **A 4-row `GrossProfit` tag is a partial disclosure, not the consolidated line.**
  COST's produced a 5.6% gross margin against a true ~12.9%. When the direct
  series is under half the length of revenue, prefer `revenue - COGS`.
- **The qual cache key is a hash of the RENDERED evidence pack, so any cosmetic
  edit to pack formatting invalidates all 500 companies.** Learned the expensive
  way on 2026-08-08: adding an empty `{where}` interpolation to the excerpt header
  changed every pack by one space and forced a full regeneration, burning about two
  hours of GPU. Before touching `evidence.py`'s string assembly mid-run, check
  whether the change alters the rendered text at all. The durable fix (see
  `PLAN.md`) is to key on semantic content — fact-sheet values plus the chosen
  chunk texts — rather than the assembled string with its headers.
- **THE RECURRING BUG ON THIS BOX: graceful degradation hiding a wiring failure.**
  Four separate instances on 2026-08-13, every one of which produced plausible
  output and exit code 0:
  1. `getattr(fact, "value", None)` — the field is `Fact.val`, so every EDGAR fact
     read as `None` and a study reported "no annual facts".
  2. `FE_ROIC_BANDS` has 4 thresholds but `fe.py` hardcoded a 4-entry ladder, so
     ROIC below 4% raised `IndexError`, the engine caught it as "FE scoring
     failed", and **23 companies silently lost the whole 18-point component**.
  3. `r.get("cik") or et.cik_for(...)` — **NaN is truthy**, so a missing CIK won
     the `or`; all 400 S&P 400 rows became `"0000000nan"`, collided in the dedupe,
     and the crawl ran ONE company and said "0 scored, 1 failed".
  4. One `'Infinity'` string in `pe` made `to_parquet` raise; it was caught as a
     WARNING, so **scores.parquet froze at 1,139 rows while scores.csv had 1,497**
     — and the parquet is what the UI and every study read.

  The rule: **an except/`or`/default that covers a WIRING error must be loud.**
  Thin data is a fallback; an absent column, a length mismatch, a non-finite
  number or a failed write is a bug. Log at ERROR and say what it costs, or raise.
  When a run reports success, check a count you can predict independently — rows
  written vs rows on disk, universe in vs universe out.
- **A SAFETY GATE firing in the wrong place is the same failure class**, and so is a
  wrapper that reads `$LASTEXITCODE` after the wrong command. On 2026-08-16 the qual
  task logged `done exit=0` having folded nothing: the probe gate (>50 symbols needs a
  probe under 7 days old) refused a 99-company *fold*, which is a re-score from disk at
  0.6-0.8 s/symbol, not the cold crawl the gate is calibrated for — and `run_clab.ps1`
  read the exit code only after the export that follows the fold, so the refusal never
  reached the task's status. A gate that can refuse a REQUIRED maintenance step must
  either exempt it explicitly and say so in the log, or its refusal must be fatal. Never
  both silent and non-fatal.
- **A graceful fallback will hide a wiring bug, so a MISSING column must raise.**
  `panel.py` computed `fe_sector_scored` and never copied it onto the row. Every
  sector distribution then filtered to zero peers, `_fe_sector_relative` took its
  "too few peers → use the absolute basis" path for all 67,889 rows, and the run
  printed `fe_basis: {'absolute': 67889}` and exited 0. F1 was measured as having
  no effect when it had simply never run. `score_panel(sector_relative=True)` now
  raises on a missing column, and both it and `apply_sector_relative` raise if
  **zero** rows end up on the relative basis. Thin data is a fallback; an absent
  column is a bug.
- **ONE derivation, ONE filter, EVERY window.** `diluted_shares_ttm` went through E28's
  `ttm_share_count` outlier filter; `diluted_shares_ttm_prior` kept a hand-rolled
  `sum(facts[-4:]) / 4.0`. Two code paths for one quantity, only one filtered, so the
  prior window ran ~25% light and median `dilution_yoy` read **+32.5%** — almost exactly
  4/3. Every company in the universe looked like it was issuing a third of its shares a
  year, AAPL and NVDA included, and `bs_dilution` earned nothing in **all eleven sectors**.
  **A sub-test that is constant across every sector is the symptom to look for** — that is
  what `clab/research/e30_sector_audit.py` exists to find.
- **A revenue tag can be a FRAGMENT, and chain order will happily prefer it.** EQR files
  `RevenueFromContractWithCustomerIncludingAssessedTax` of **$384,000** (management fees)
  beside `Revenues` of **$2,699,485,000**; the chain preferred the fragment and its
  `revenue_ttm` read $216,000, giving an operating margin of 5,373. 17% of Real Estate
  and 16% of Financials carried a revenue number this way. Two rules now:
  - **Inside the `revenue` chain, a fresh tag that dominates on SHARED periods wins**,
    because every chain member is a candidate *total* and a component cannot exceed its
    own total (`tags._prefer_consolidated`). Freshness is still decided first, so the
    NVDA retired-tag rule is untouched.
  - **That argument does NOT extend outside the chain.** Lease income is not a candidate
    total — Iron Mountain's storage rent runs 1.72x its contract-revenue tag because they
    are two *halves* of $7.56bn, and an early draft swapped the total for the half. The
    lessor substitute fires only on the **stranded** case (EQR's revenue tags both stop at
    2020-03-31 while `OperatingLeaseLeaseIncome` runs to 2026-06-30), and even then the
    series must overlap, agree in magnitude there (0.67x–1.5x), and yield a usable TTM.
  - The bank substitute (`interest_income_operating + noninterest_income`) was gated on
    `len(revenue) == 0` and so never fired for FITB, whose chain returned $617m of card
    fees. **An empty series is a fallback; a series dwarfed by a more consolidated
    measurement of the same thing is a bug.**
  - **A STRANDED line is the same bug as a fragment, and its derivation already exists.**
    A filer that stops tagging `GrossProfit` or `OperatingIncomeLoss` leaves a
    *full-length* series years in the past: it passes the length test written for COST's
    4-row partial disclosure, then pairs a 2020 numerator with 2026 revenue, and
    `RATIO_PERIOD_MAX_GAP_DAYS` refuses it — so the point was **withheld while
    `revenue - cogs` or the EBIT reconstruction sat there current and usable**.
    `GrossProfit` is stale for 6.4% of filers, `OperatingIncomeLoss` for 4.7%. Both
    derivations now fire on the stranded case as well as the absent one, through
    `_rescues_a_stranded_series` — reach further AND agree on the overlap.
  - **A/B any change to the correctness core before committing it.** Three drafts of this
    one were wrong and each was caught by re-deriving `revenue_ttm` over 220–260 cached
    filings with the change on and off. The signature of a repair is directional: the
    final chain fix moved 10 companies and **every one increased**.
- **UNDEFINED is not MISSING, and the soft rule is load-bearing (E31).**
  `resolve_status` grants `NOT_APPLICABLE` only on profile nomination **AND** an absent
  value, so a suppression whose reason is *meaningless* rather than *missing* almost never
  fires — 93.8% of banks carried an interest-coverage score. `SectorProfile.undefined`
  now suppresses regardless of the value, and **its bar refused 35 of 40 candidates.**
  Only `MORTGAGE_REIT` was admitted, because it is the only homogeneous bucket in the
  file. **Do not extend `undefined` without adding a written definitional argument to
  `journal/experiments/E31_undefined_map.md`** — a test asserts the set.
  **`FINANCIAL` is not a profile of banks**: 63 of its 192 members are Visa, Mastercard,
  CME, S&P Global, BlackRock, and even Dolby (87.6% gross margin). A hard suppression
  there would delete real measured signal, so **the two-part test is silently protecting
  the framework from a coarse classification** — that is why it must stay.
- **A GICS sector VETOES a SIC-derived archetype it contradicts.** SIC 6700–6799 is
  "Holding and Other Investment Offices" and contains operating companies in a financial
  wrapper: 6792 oil royalty traders (TPL), 6794 patent owners and lessors (Dolby,
  InterDigital), 6795 mineral royalty traders (Royal Gold). Nine companies carried a
  profile contradicting their own stored sector. The veto only ever falls **back to
  STANDARD** — it can never invent a suppression — and an absent sector vetoes nothing.
  Expect coverage to FALL for the companies it moves (RGLD 0.71 → 0.61): sub-tests that
  were excused as `NOT_APPLICABLE` become honest `NO_DATA`.
- **`--symbols` used to silently rewrite a company's PROFILE.** `batch.py` built its
  lookup from one tier and gave anything missing a bare CIK row with an empty
  `sub_industry` — the only thing separating a mortgage REIT from an equity REIT.
  Re-scoring the nine mortgage REITs by name reclassified all nine and moved NLY's
  coverage 0.500 → 0.446, so **the same company scored two ways depending on how the
  crawl was invoked**. It now searches every tier; the true no-tier case logs a WARN. If
  you re-score one name, check the log for `taking its classification from`.
- **A VERIFICATION THAT READS THE WRONG FIELD PASSES QUIETLY, and that is worse than no
  check.** E34's first draft labelled **147 companies "no repurchases" while they held
  real buybacks — JPM at $31.67bn.** My check for exactly that filtered on `s.get("note")`;
  the field is `threshold_note`. It read `None` for every row, the substring never
  matched, and the check reported clean. **When a check returns zero, confirm the query
  can return non-zero at all** — assert a known-positive case before trusting a null.
  Same family as `getattr(fact, "value")` and NaN surviving `is not None`.
- **A guard must key on the CONDITION, not on "the branch above declined."**
  `elif dil is not None` fired whenever the normal path declined — and that path also
  declines when repurchases *exist* but FCF is zero, negative or undefined, which is every
  bank. `elif buybacks is None and dil is not None` is the correct form.
- **Margin of safety divides by fair value, so a NEGATIVE fair value flips its sign.**
  `(fair - price) / fair` guarded by `if fv` catches zero and nothing else: HR reported
  **+251,695%** on a fair value of −$0.008. It is now withheld unless the fair value is
  finite, strictly positive and not flagged implausible — and the DCF sheet **sorts on that
  column**, so a broken DCF ranked as the cheapest company in the workbook.
- **Every user-facing total derives from `rubric.points_in()`.** The framework went
  100 → 94 at E26 and the labels did not follow for weeks — the company page said
  "Excluding Entry /95" when the answer was **92** (total minus EN, and EN had dropped
  5 → 2). `tests/test_label_drift.py` fails the build if a literal returns.
- **A before/after that straddles midnight is confounded by the band hysteresis.** E33's
  measurement showed 100 band changes; **85 were the calendar day rolling over** and
  confirming pending transitions, 13 were the fix, 2 were prices. Check
  `band_reading_date` before attributing anything to a change.
- **`isinstance(v, (int, float))` is NOT a number check — NaN passes it.** And NaN does
  not merely skew a list, it silently scrambles the ORDER, because every comparison
  against it returns False. Measured 2026-08-25 on the real 1,501-row parquet: three
  companies have a null `score`, and with them included the Real Estate median read **12**
  — its minimum — instead of 33. `xlsx_export._finite` is the guard; use it anywhere a
  column is sorted, medianed or `max()`-ed, and note that it also excludes `bool`, which
  would otherwise sort as 1. Same family as the `'Infinity'` parquet bug below.
- **`ws.append([])` moves openpyxl's write cursor but not `max_row`** (it writes no
  cells), so `header_row = ws.max_row + 1` is off by one after a spacer row. Read
  `ws.max_row` back *after* appending the header instead of predicting it, or the
  bolding lands on the blank row and a chart `Reference` aims one row high.
- **`Out-File -Encoding utf8` writes a BOM in PowerShell 5.1**, so a commit message
  file produced that way puts an invisible `U+FEFF` at the front of the subject
  line and it stays in `git log` forever. Write message files with
  `[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))`. Also:
  `git commit -m` with escaped quotes fails here (exit 129) — always use `-F`.
- **A ticker is not always a safe filename.** `CON`, `PRN`, `AUX`, `NUL`, `COM1-9` and
  `LPT1-9` are Windows device names. Python's `open()` will happily create
  `E22_raw/CON.json` — and then **git cannot read it**: `git add -A` died with
  `open("journal/experiments/E22_raw/CON.json"): No such file or directory` for a file
  sitting right there, and refused to stage the entire tree, which reads exactly like an
  antivirus lock and is not one. Deleting it needs the `\\?\` prefix. `CON` is a real
  S&P constituent. Every path built from a ticker goes through
  `clab/research/e22_judgement_backtest.py:safe_stem`.
- **`DEFA14A` is not the proxy.** The submissions feed returns it FIRST because it is
  filed later, and it is "additional soliciting material" — a voting-results letter or a
  slide deck. Measured 2026-08-22: AAPL's newest `DEFA14A` is 3,866 characters and
  mentions neither beneficial ownership nor tenure nor founders; NVDA's stripped to zero.
  The real proxy is `DEF 14A`, 260k–570k characters, and it carries all three. Filter on
  the exact form or the CEO block reads a press release.
- **Never let `inf` reach JSON, parquet or CSV.** Interest coverage is capped at
  999 with an `interest_coverage_uncapped` flag.
- **`or` on a pandas Series raises.** Bit the Wikipedia changes-table parser; use
  explicit `is not None` checks.
- pandas 3.0 / numpy 2.4 in this venv. Wikipedia tables are matched by **header
  signature**, never by table index, because their ordering changes.
- **Stage an external-research request the same NEW YORK day Codex will finalize it.**
  `finalize.check_request` compares `generated_at` converted to NY against today in NY
  and refuses everything otherwise (`frozen request is dated X, not today (Y)`). It has
  killed a staged batch twice: b2 was staged 09-08 and rebuilt 09-09, and b3 was staged
  2026-09-10T00:18Z — which is 09-09 20:18 NY — and was dead before Codex opened it. A
  request staged in the evening also dies at NY midnight while the batch is still
  running. Re-staging is safe and cheap: `request_id` hashes roster+depth+spec+sample
  and NOT the timestamp, so the same `--symbols` roster rebuilds to the same id,
  `roster_sha1` and `spec_fingerprint`, and `store.begin` is idempotent on `request_id`.

**The weekly artifact is `data\exports\company_lab_latest.xlsx`** — a stable name
refreshed by every crawl beside the dated archive, so the user's shortcut keeps
working. `CompanyLabCrawl` (Sat 03:00) rebuilds it; `CompanyLabSnapshot` (Sat
12:00) records the week so the next build can diff. The Changes / Sectors /
Findings sheets sit **directly behind Rank on purpose**: 500 confident-looking
scores with no measured predictive power beside them is misleading by omission.

**Cross-sector comparison uses `sector_neutral_score`, not `score` (2026-08-25).** The
Rank sheet carries `sector_rank` / `sector_rank_n` / `sector_neutral_score` in the first
screenful, the Sectors sheet ranks the top 10 within each sector, and all three of Rank,
Sectors and Findings repeat one sentence saying so. Measured that day: median `score`
runs Information Technology **59** (94% banded) to Real Estate **33** (34% banded), a
**26-point** spread, on top of E03 R1's finding that 95.6% of the ranking's power was
sector selection. Nothing was rescored and no weight moved — this is presentation, and it
carries no claim that either column predicts returns (E14 passed all four of its
registered criteria and still fails the promotion gate). **The trap:
`sector_neutral_score` is a percentile of `composite_strict`, while the `score` beside it
is the ex-entry sum normalised to 100 — they do not order identically, which is why every
row carries `sector_neutral_score_col`.** `sector_rank` is a count, not a statistic, so it
skips the `MIN_PEERS` floor that makes the percentile abstain.

`clab/scoring/rubric.py` is the first file to read: it holds every threshold and
every resolution of an underspecified corner of the framework (labelled A1-A10),
so a disagreement is a one-line edit rather than an archaeology project.
